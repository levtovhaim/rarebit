# The local stack

Everything the game needs, on one machine, run the way the cluster will run it ([ADR 0024](../docs/adr/0024-local-stack-with-compose-and-nginx.md)).

```bash
make up      # build both images, start the stack, wait until every service is healthy (about 40 s)
make smoke   # the bots image: three bots play a full game through nginx
make down    # stop and remove the containers, the network and the database
```

```
phone/bots ──> nginx 127.0.0.1:8080 ──> game-1 ─┐
                                     └─> game-2 ─┴──> redis
                                                 └──> validator ──> postgres <── migrate (once)
```

| Service | Image | Healthy when | Waits for |
|---|---|---|---|
| `postgres` | `postgres:18.7` | `pg_isready` over TCP | - |
| `migrate` | `rarebit-validator:dev`, `migrate` | (a job: exits 0 once the schema and word lists are loaded) | postgres healthy |
| `validator` | `rarebit-validator:dev`, `serve` | `/validator check-ready` (its `/readyz`) | migrate finished successfully |
| `redis` | `redis:8.10.3-alpine` | `redis-cli ping` | - |
| `game-1`, `game-2` | `rarebit-game:dev` | `dist/check-ready.js` (its `/readyz`) | redis healthy |
| `nginx` | `nginx-unprivileged:1.31.7` | `wget` on its own `/healthz` | both game replicas started |
| `bots` | `rarebit-bots:dev` | (not started by `make up`: the `tools` profile; `make smoke` runs it) | - |

Why those conditions:
- **`migrate` must finish, not just start:** before it does, the validator has no schema and no word lists, and its readiness fails.
- **The game waits only for Redis**, its one hard dependency. It doesn't wait for the validator: without categories, rounds wait and retry, as they would in the cluster, where nothing orders startup.
- **nginx waits for the replicas to start, not to be healthy:** it routes around one that's down, so a broken replica doesn't keep the entry point closed.

`make up` uses `docker compose up --wait`, which returns once every healthcheck passes, so a `make smoke` right after it finds a ready stack. `make smoke` builds the bots image and runs `docker compose run --rm bots synthetic`: the bots reach the game through nginx (`BOTS_URL=http://nginx:8080`), like any player ([ADR 0025](../docs/adr/0025-bots-image-and-smoke-from-it.md)).

## How it runs

- **Like the cluster:** our services (and Redis) run with a read-only root filesystem, no Linux capabilities, no privilege escalation and a non-root user. Postgres is the stock image.
- **One port:** only nginx publishes one, on `127.0.0.1`. The rest talk on the stack's own network.
- **No sticky sessions:** nginx spreads WebSockets over the two game replicas (round robin). Every room is in Redis, so a player on `game-1` and one on `game-2` share a game (ADR 0019).
- **Secrets:** the Postgres password is random, generated by `make up` into `compose/.env` (git-ignored, read by compose), and removed by `make down`.
- **Data:** the database lives in an anonymous volume and Redis in memory; `make down` removes both.
- **Shorter games** than the server's defaults: 15 s rounds, 3 rounds, a 5 s quick-play countdown. Override them with `RAREBIT_ROUND_SECONDS`, `RAREBIT_MAX_ROUNDS` and `RAREBIT_COUNTDOWN_SECONDS`, and the port with `RAREBIT_PORT`.
- **Origins:** the game accepts WebSockets from `http://localhost:8080` and `http://127.0.0.1:8080`; `make smoke` sends the first.

## Drills

Both run against this stack with the bots' chaos observer:

```bash
docker compose -f compose/compose.yaml run --rm bots observe --rooms 3 --duration 1 &
sleep 12; docker kill rarebit-game-1-1                    # or: docker compose -f compose/compose.yaml stop game-2
wait
```

Last runs (2026-11-25; the second kill drill with the bots image as the observer: 3/3 games, 5 resumes):

| Drill | Games | Result |
|---|---|---|
| `docker kill` of game-1 mid-game | 3 | all finished; 4 bots resumed on game-2; scores checked |
| `docker compose stop game-2` mid-game (SIGTERM, a drain) | 3 | all finished; 4 bots got `server:draining` and moved; game-2 drained and exited 0 |

## Where it differs from the cluster

- **A draining replica still gets new connections.** It refuses the WebSocket upgrade with `400` (nginx logged two during the drain drill), and the client's reconnect lands on the other replica. Open-source nginx has no active health checks; in the cluster, readiness takes a draining pod out of the Service, which is what the drain delay is for.
- **`docker kill` isn't a crash.** `restart: unless-stopped` restarts a process that dies on its own, but Docker counts `docker kill` as a manual stop, so the replica stays down until `docker compose start game-1`. Kubernetes restarts a killed pod either way.
- **No resource limits:** the containers share the machine.

## Troubleshooting

- **`make up` times out:** `docker compose -f compose/compose.yaml ps` shows which service isn't healthy; `docker compose -f compose/compose.yaml logs <service>` shows why.
- **`required variable RAREBIT_PG_PASSWORD is missing`:** a compose command run directly before `make up` created `compose/.env`.
- **Port 8080 is taken:** `RAREBIT_PORT=8090 make up`, then `RAREBIT_PORT=8090 make smoke`.
- **`make smoke` fails:** the reason is in its `game` line; [docs/runbooks/bots.md](../docs/runbooks/bots.md) says where to look.
